## 概述

前缀和可以简单地理解为**数列的前 n 项和**，是一种重要的预处理技巧

前缀和的核心思想是**提前计算并存储数组的部分和**，当需要查询某个区间的和时，直接通过已存储的前缀和进行推导，避免重复计算，它能够将原本需要**O(n)** 时间复杂度的区间求和操作优化到**O(1)**，大大提高了数据查询的效率。

**例**：  
对于数组`nums = [1, 2, 3, 4, 5]`  
其前缀和数组 `prefix = [0, 1, 3, 6, 10, 15]`
- 区间 `[1, 3]`（元素 2、3、4）的和 = `prefix[3 + 1] - prefix[1] = 10 - 1 = 9`
- 区间 `[0, 2]`（元素 1、2、3）的和 = `prefix[2 + 1] - prefix[0] = 6`
- 区间`[l, r]`中的元素和 = `prefix[r + 1] - prefix[l]`
这里将`prefix[0]`设成 0 的原因就是能够使得前缀和总是成立，否则计算从 0 开始的区间元素和时，就会少掉后面那一项
## 适用场景

- 预处理：可用于直接计算子数组和
- 计数：借助[[哈希表]]计算具有特殊性质的子数组
- 查询：适合**多次查询区间和**，预处理 O (n)，查询 O (1)

### 前缀和数组 与 单变量 sum

在做前缀和题目时，有时候需要用到前缀和数组，有时候使用一个 sum 就行，它们之间有什么区别呢？

- 当我们需要多次**查询**特定区间的前缀和时，需要用到数组（我觉得主要是因为数组有下标）
- 当我们不需要查询具体的区间，比如说只关心某一特定数组和的存在性时，或者这个前缀和是一次性的，不需要回溯的，就用 sum

## 总结

对一个数组**进行**“**前缀和**”**操作**，就能得到一个**值为**“**该数组内元素之和**”**的元素**，这算不算一种封装呢？我们考虑的对象就从“**一组数**”变成了“**一个数**”

前缀和就是在为“**对容器中元素的同一操作进行存档**”，比如我**每天**都要花**一段时间**（元素）**锻炼身体**（操作），然后从月初开始，**每一天**都记录**这个月一共**锻炼了多少时间，如果我想知道从15号到20号（**某一区间**）锻炼了多少时间，就只需要将20号的记录减去14号的记录就行了

进一步的，同一操作会赋予部分前缀和**某些性质**，如果我们想对具有这些性质的前缀和**计数**，就可以借助[[哈希表]]。我们已经知道如何计算区间`[l, r]`中的元素和，这个元素和的性质就是由`prefix[r]`和`prefix[l]`决定的，所以，想要求得**具有某种性质的子数组和**，可以用到类似[[枚举右，维护左]]的方法，枚举`prefix[r]`，然后将相同性质的前缀和用[[哈希表]]存储。
