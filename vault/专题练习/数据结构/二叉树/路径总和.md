[路径总和](https://leetcode.cn/problems/path-sum/)
## 题目拆解 / 题意分析

很直白的题目，遍历每个路径，同时记录每条路径上的节点和，判断是否等于目标值

## 解题思路

**深度优先搜索（DFS）** + **[[递归]]**：

1. [[递归]]先序遍历[[二叉树]]，每到一个节点，将节点值累加，直到叶子节点，如果等于目标值，返回 true，否则继续，直到遍历整棵树
2. [[递归]]遍历[[二叉树]]，每到一个节点时，将 `targetSum` 减去当前节点值，得到 “剩余需要凑的和”，为零则满足

## 代码实现

```cpp
class Solution {
public:
    bool hasPathSum(TreeNode* root, int targetSum) {
        auto dfs = [&](this auto&& dfs, TreeNode* node, int currentSum) -> bool{
            if (!node) {
                return false;
            }
            currentSum += node->val;
            if (!node->left && !node->right) {
                return currentSum == targetSum;
            }
            return dfs(node->left, currentSum) || 
                   dfs(node->right, currentSum);
        };
        return dfs(root, 0);
    }
};
```

简洁写法：

```cpp
class Solution {
public:
    bool hasPathSum(TreeNode* root, int targetSum) {
        if (!root) {
            return false;
        }
        if (!root->left && !root->right) {
            return targetSum == root->val;
        }
        return hasPathSum(root->left, targetSum - root->val) ||
               hasPathSum(root->right, targetSum - root->val);
    }
};
```

## 复杂度分析

### 时间复杂度：**O(n)**

其中 n 为二叉树的节点个数

### 空间复杂度：**O(n)**

最坏情况下，二叉树退化成一条链，递归需要 O(n) 的栈空间

## 总结 / 错误反思

一开始我还没搞明白`currentSum`是怎么工作的，为什么不会重复计算。后来才意识到这是一个局部变量，实际上每调用一次递归函数，都会有一个单独的`currentSum`存在栈帧里，记录“到当前节点为止的路径和”。在基准情况完成计算，栈帧一层一层出栈时，这个`currentSum`自然就没了，他不是一个全局变量

**更准确的说**：调用 `dfs(node, currentSum, targetSum)` 时，由于参数是**值传递**，计算机其实会为 “新的递归调用” **拷贝一份`currentSum`**，并把这份拷贝存到新创建的栈帧里。这份拷贝只负责记录 “从根到当前 `node` 的路径和”，和其他栈帧里的 `currentSum` 毫无关系（比如左子树栈帧的 `currentSum` 不会影响右子树的）。

等到基准情况（叶子节点）判断完，或者当前分支的递归结束，对应的栈帧会从调用栈里弹出 —— 栈帧里存的那份 `currentSum` 也会跟着 “消失”，不会留下任何痕迹，自然不会干扰其他分支的计算。

## 知识补充

### 一、什么是 “栈帧”？

栈帧（Stack Frame）是计算机在执行函数调用时，在**栈内存**中为该函数分配的一块 “临时存储区”，用于保存以下关键信息：

- **参数**：函数调用时传入的参数（如 `dfs(node, currentSum, targetSum)` 中的 `node`、`currentSum`、`targetSum`）
- **局部变量**：函数内部定义的临时变量（如递归过程中中间计算的和）
- **返回地址**：函数执行完毕后，程序需要回到的 “调用位置”（比如 `fun(5)` 调用 `fun(4)` 后，要记住执行 `5 * fun(4)` 中 `*5` 的位置）

### 二、计算机如何运行递归程序？

递归的本质是 “函数调用自身”，计算机通过 **调用栈（Call Stack）** 管理多层函数调用的栈帧，整体分为两个阶段：**递推（层层深入）** 和 **回归（逐层返回）**。

#### 以 “阶乘函数 `fun(n) = n * fun(n-1)`” 为例（计算 `fun(3)`）：

```cpp
int fun(int n) {
    if (n == 1) return 1;
    return fun(n-1) * n;
}
```

##### 1. 递推阶段：栈帧 “层层压入” 调用栈

- 调用 `fun(3)`：系统为 `fun(3)` 创建**栈帧 1**，保存：
    - 参数 `n=3`，
    - 返回地址（等待 `fun(2)` 结果后执行 `*3`），
    - 局部变量（无显式局部变量，隐式保存乘法状态）。
        由于 `n≠1`，需要调用 `fun(2)`，因此暂停 `fun(3)`，先处理 `fun(2)`。
- 调用 `fun(2)`：系统为 `fun(2)` 创建**栈帧 2**，保存：
    - 参数 `n=2`，
    - 返回地址（等待 `fun(1)` 结果后执行 `*2`）。
        由于 `n≠1`，需要调用 `fun(1)`，暂停 `fun(2)`，处理 `fun(1)`。
- 调用 `fun(1)`：系统为 `fun(1)` 创建**栈帧 3**，保存：
    - 参数 `n=1`，
    - 返回地址（无后续操作，直接返回 `1`）。
        此时 `n=1` 满足终止条件，直接返回 `1`，**栈帧 3 弹出**。

##### 2. 回归阶段：栈帧 “逐层弹出” 并计算结果

- `fun(1)` 返回 `1`，回到 `fun(2)` 的栈帧 2：执行 `1 * 2 = 2`，返回 `2`，**栈帧 2 弹出**。
    
- `fun(2)` 返回 `2`，回到 `fun(3)` 的栈帧 1：执行 `2 * 3 = 6`，返回 `6`，**栈帧 1 弹出**。

##### 3. 调用栈的动态变化（简化示意）

```text
递推阶段（栈帧压入）：
| fun(3) n=3, 等待fun(2)→*3 | ← 栈顶
| fun(2) n=2, 等待fun(1)→*2 |
| fun(1) n=1, 返回1         | ← 栈顶（立即弹出）

回归阶段（栈帧弹出）：
| fun(3) n=3, 等待fun(2)=2 → 计算3*2=6 | ← 栈顶（弹出后结束）
| fun(2) n=2, 等待fun(1)=1 → 计算2*1=2 | ← 栈顶（弹出）
```
